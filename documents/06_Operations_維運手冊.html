2. 常見故障排查 SOP

🟡 警告 — 地圖上無測站資料顯示 / 測站全部變灰
  1. 開啟瀏覽器 F12 → Network 分頁，確認 /api/sensors 和 /api/observations 是否正常回傳 200。
  2. 若 /api/sensors 回傳空陣列 []，表示 Supabase sensors 表為空 → 執行 Poller 初始化：
    cd scripts && npx tsx pollIoT.ts
  3. 若 /api/observations 回傳空陣列，表示無當前時間點的觀測資料 → 確認 Poller 是否正常執行，檢查 scripts/run_poller.log 最後幾行。
  4. 若兩個 API 均正常，但地圖無顯示 → 確認 NEXT_PUBLIC_MAPBOX_ACCESS_TOKEN 是否有效，Mapbox 控制台是否有 Token 超額或過期錯誤。
🟠 嚴重 — API 回應超時 / Vercel Function Timeout
  1. 前往 Vercel Dashboard → Functions → 查看最近的 Function 呼叫日誌，確認是哪支 API 超時。
  2. 若是 /api/anomalies 超時，可能原因：Supabase 查詢量過大 → 確認 observations_5m 資料是否超過 7 天未清理，執行清理函式：
    SELECT cleanup_old_observations();
  3. 若是 /api/completeness 超時，原因同上，資料量過大 → 同步清理。
  4. Vercel Hobby 方案 Function 執行上限為 10 秒，若問題持續，考慮升級至 Vercel Pro（60 秒上限）。
🟠 嚴重 — Poller 腳本停止運作 / 資料不再更新
  1. 開啟 scripts/run_poller.log，檢查最後一行時間戳記，若超過 15 分鐘未更新即為異常。
  2. 查看 Log 最後幾行是否有錯誤訊息：
    • ❌ 缺少 SUPABASE_URL 或 SUPABASE_SERVICE_ROLE_KEY：環境變數未設定，確認 .env.local 是否存在。
    • FetchError / ETIMEDOUT：OGC API 或 Supabase 網路問題，等待網路恢復後會自動重試。
    • 其他未預期錯誤：將錯誤訊息回報給開發團隊。
  3. 手動重新啟動 Poller：
    cd C:\GoogleAntigravity\2026IoTcenter\scripts
npx tsx pollIoT.ts
  4. 確認 Windows 工作排程器任務「IoT Poller」是否仍啟用且未因錯誤停止。
🔴 緊急 — Supabase 連線中斷 / 系統自動降級
  1. 系統會自動切換至 Tier 2（SQLite）或 Tier 3（Mock），服務不中斷，但資料將停止更新。
  2. 確認 Supabase 服務狀態：前往 status.supabase.com。
  3. 若為 Supabase 服務故障，等待其恢復即可，系統會自動重新連線。
  4. 若 Supabase 帳號或 Key 問題，重新確認 Vercel 環境變數並重新部署：
    cd dashboard && npx vercel --prod --yes

3. 資料補件作業程序

當 Poller 因網路中斷或異常停止，導致一段時間的觀測資料缺漏時，請執行以下補件程序：

  1. 確認缺漏時間範圍（查看 run_poller.log 中斷點）。
  2. 手動多次執行 Poller，每次帶入不同的歷史時間區間（Poller 目前設計為抓取最新資料，如需歷史補件請確認 OGC API 是否提供歷史查詢功能）。
  3. 直接在 Supabase SQL Editor 中確認補件是否完成：
    SELECT COUNT(*), MIN(bucket_time), MAX(bucket_time)
FROM observations_5m
WHERE bucket_time BETWEEN '2026-07-13 00:00:00' AND '2026-07-13 23:59:59';

5. 系統重啟程序

5.1 重新部署前端（Next.js）

cd dashboard
npx vercel --prod --yes

5.2 重新啟動 Poller 排程

  1. 開啟 Windows 工作排程器。
  2. 找到「IoT Poller」任務，右鍵 → 執行，確認是否正常啟動。
  3. 或直接執行 scripts\run_poller.bat 測試。
