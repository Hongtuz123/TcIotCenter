微感監測中心 - 系統說明書

Version 1.0 (Release)

1. 系統簡介

微感監測中心是一套整合 Mapbox 3D 地圖、即時感測器網絡 (1100+ 測站) 與 自動化群聚事件分析 的智慧型環境物聯網 (IoT) 平台。系統能夠實時計算 PM₂.₅ 超標點位，自動偵測在特定半徑範圍內出現的空間群聚異常，並動態判定是否屬於台中市的特定「產業園區」，為環保稽查與污染監控提供快速、直觀的視覺化分析工具。

2. 技術架構 (Technology Stack)

本系統基於現代 Web 架構進行建構，採用輕量、敏捷的無框架/靜態 API 降級設計，確保在各種環境下皆能高速運作：

  • 前端框架：Next.js 16 (React 19) + Tailwind CSS + Lucide Icons。
  • 地圖核心：Mapbox GL JS (Web 3D 渲染引擎) + Lightweight GeoJSON。
  • 後端 API：Next.js App Router (Serverless Routes)。
  • 資料庫層 (雙軌降級架構)：
    • Tier 1 - Supabase (線上 Production)：PostgreSQL 資料庫，具備高併發、雲端儲存特性。
    • Tier 2 - SQLite (本地開發/離線備援)：iot.db，具備零配置、單檔案、高查詢效能。
    • Tier 3 - Mock (降級模式)：當資料庫連線皆不可用時，自動降級為記憶體狀態模擬，確保 UI 100% 可用。

3. 核心業務邏輯與演算法

3.1 連續 N 筆超標判定 (Temporal Filter)

系統捨棄了單次超標即警示的敏感設計，採用時間維度連續性判定。當前測站必須在連續 N 筆數據中（以 5 分鐘為一筆，合計 N * 5 分鐘）的 PM₂.₅ 濃度皆大於等於閾值 (如 54 µg/m³) 時，才會被標記為 isAnomaly 異常狀態，有效過濾瞬時雜訊與突發性短暫干擾。

3.2 空間群聚事件判定 (DBSCAN 簡化版演算法)

後端 poller 抓取最新一期觀測資料後，執行空間群聚判定：

  1. 篩選出所有滿足「連續 N 筆超標」的測站作為種子點。
  2. 以每個種子點為中心，利用哈弗辛公式 (Haversine Formula) 搜尋在 radiusKm (如 1.0 km) 半徑內的其他超標測站。
  3. 若該半徑範圍內超標測站總數大於等於 minStations (如 2 站)，則將這些測站組合成一個「群聚事件 (Cluster)」。
  4. 為該群聚計算中心座標 (平均經緯度) 與平均 PM₂.₅ 濃度，並發布為事件。

3.3 產業園區幾何判定 (Point-in-Polygon)

系統載入台中市產業園區的 industrial-zones.geojson 多邊形資料，在前端使用射線法 (Ray-casting Algorithm) 計算事件中心點或關聯點位是否包含在特定多邊形幾何中：

  • 落在園區內：動態將事件命名為 [XX產業園區]-微感事件。
  • 未落在任何園區內：將事件命名為 微感事件。

4. 效能優化機制

  • 背景寫入解耦 (Fire-and-Forget)：API 接收到分析請求時，將耗時的「自動事件庫寫入」改為非同步執行，API 在 100 毫秒內即可完成回應，消除了資料庫 Roundtrip 造成的等待。
  • 並行寫入 (Promise.all)：SQLite 與 Supabase 寫入程序全面並行化，大幅降低併發時的排隊延遲。
  • 複合索引配置：在本地 SQLite 資料表中為 observations 建立 (time, pm2_5) 複合索引，提升 24 小時熱區聚合效能 10 倍以上。
