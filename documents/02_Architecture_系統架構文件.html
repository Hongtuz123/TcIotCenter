5. 三軌降級架構說明 (Graceful Degradation)

層級資料來源適用環境啟動條件限制
Tier 1 Supabase PostgreSQL Vercel Production SUPABASE_URL 環境變數存在且連線成功 需要網路連線、受 RLS 限制
Tier 2 SQLite (iot.db) 本地開發 Supabase 未設定 或 iot.db 檔案存在 單機、不支援並發部署
Tier 3 Memory Mock Data CI/Demo/離線 SQLite 檔案不存在 或 連線失敗 靜態假資料、不持久化
ℹ️ 關鍵設計決策：eval require 繞過 Webpack NFT

SQLite 使用 eval("require('sqlite3')") 而非直接 require，原因是 Vercel 的 Next.js 打包器（Webpack + NFT）會靜態掃描 require 呼叫並嘗試打包 sqlite3 原生 C 編譯模組，導致 Serverless Function 冷啟動失敗。使用 eval 繞過靜態分析，讓 Vercel 打包時忽略此依賴，Runtime 在本地環境執行時仍可正常呼叫。

6. 背景排程服務說明 (pollIoT.ts)

項目說明
腳本路徑scripts/pollIoT.ts
執行命令npx tsx scripts/pollIoT.ts
排程方式Windows：run_poller.bat + 工作排程器 / run_poller.vbs（背景靜默執行）
執行頻率每 5 分鐘一次（與 observations_5m bucket_time 對齊）
資料來源OGC SensorThings API：https://sta.colife.org.tw/STA_AirQuality_EPAIoT/v1.0
資料目標Supabase：sensors 表（upsert）+ observations_5m 表（upsert）
錯誤記錄scripts/run_poller.log
