2. 環境變數清冊

在 dashboard/.env.local 建立以下設定（此檔案已加入 .gitignore，請勿提交至版本庫）：

# ── Mapbox（前端 Public Token，限制 Domain） ──
NEXT_PUBLIC_MAPBOX_ACCESS_TOKEN=pk.eyJ1IjoiWXXXXXXX...

# ── Supabase（後端 Service Role Key，嚴禁洩漏至前端） ──
SUPABASE_URL=https://xxxxxxxxxxx.supabase.co
SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6Ikp...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6Ikp...

# ── 認證密碼（用於 /api/login） ──
ADMIN_PASSWORD=your_secure_password_here
⚠️ 安全性警告：SUPABASE_SERVICE_ROLE_KEY 具有繞過 RLS 的最高資料庫權限，絕對不可設定為以 NEXT_PUBLIC_ 前綴開頭的變數，否則將洩漏至瀏覽器客戶端。
變數名稱說明安全層級必填
NEXT_PUBLIC_MAPBOX_ACCESS_TOKENMapbox 地圖 Token（前端 Public）低（可公開）✅
SUPABASE_URLSupabase 專案 API 端點中✅ (線上)
SUPABASE_ANON_KEYSupabase 匿名公開 Key（RLS 保護下安全）中✅ (線上)
SUPABASE_SERVICE_ROLE_KEYSupabase 後端 Master Key（繞過 RLS）🔴 高機密✅ (線上)
ADMIN_PASSWORD系統登入密碼🔴 高機密✅

3. Supabase 初始化步驟

1
建立 Supabase 專案
前往 supabase.com 建立新專案，記下 Project URL 與 anon/service_role key。
2
執行 Schema SQL
在 Supabase 後台 SQL Editor 中，完整貼入並執行 scripts/supabase_schema.sql 的全部內容。這將建立所有資料表、Index、RLS 政策與自動觸發器。
3
填寫 .env.local
依第 2 節將 Supabase URL 與 Keys 填入 dashboard/.env.local。
4
初始化測站資料
執行 Poller 一次，讓它從 OGC API 抓取台中市所有測站並寫入 Supabase：
cd scripts
npx tsx pollIoT.ts

4. Vercel Production 部署步驟

1
安裝 Vercel CLI 並登入
npm install -g vercel
vercel login
2
設定 Vercel 環境變數
在 Vercel 後台 → Settings → Environment Variables，將 .env.local 的所有變數逐一新增至 Production 環境。
3
執行 Production 部署
cd dashboard
npx vercel --prod --yes
部署成功後，終端機將顯示 Production URL：https://tc-iot-center.vercel.app

5. 本地開發環境建置

# 安裝依賴
cd dashboard
npm install

# 啟動開發伺服器（支援 Hot Reload）
npm run dev

# 瀏覽器開啟
# http://localhost:3000

本地環境若未設定 Supabase 環境變數，且 iot.db 不存在，將自動啟用 Tier 3 Mock 模式（假資料演示）。若需測試真實資料，請確保 iot.db 存在於 dashboard/ 目錄中。

6. 背景排程腳本部署 (pollIoT.ts)

Windows 工作排程器設定（建議方式）

  1. 以系統管理員身份開啟「工作排程器」
  2. 新增基本工作 → 觸發條件選「每天」→ 重複間隔設為「5 分鐘」
  3. 動作選「啟動程式」→ 程式路徑：C:\GoogleAntigravity\2026IoTcenter\scripts\run_poller.vbs
  4. 完成設定，確認工作列已啟用

run_poller.bat 內容說明

@echo off
cd /d C:\GoogleAntigravity\2026IoTcenter\scripts
npx tsx pollIoT.ts >> run_poller.log 2>&1
✅ Poller 執行記錄將輸出至 scripts/run_poller.log，可用於排查資料接入問題。
